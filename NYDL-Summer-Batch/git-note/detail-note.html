Module 1: Software Collaboration & VCS Foundations

Version Control is a system that records all changes and modifications to files over time for tracking, safety, and team collaboration.

Core Benefits of Version Control

📜 Revision History

Keeps a chronological log of all changes. If something breaks, you can instantly revert back to a working snapshot.

👤 Identity Tracking

Links every single commit to the specific author's name and email, making code auditing and communication seamless.

🤝 Team Collaboration

Allows multiple developers to work concurrently on the same codebase without overwriting each other's work.

⚙️ Automation & CI

Triggers automated test suites, build compilers, and security checks on every code submission.

⚡ Team Efficiency

Empowers developers to experiment boldly on isolated branches knowing they can safely rollback if needed.

Agile Methodology

A software development practice centered around iterative progress, small deliverables, continuous feedback, and rapid releases.

DevOps Culture

Combines Development (Dev) and IT Operations (Ops) to accelerate code delivery speed while maintaining system stability and security.

Evolution & History of Version Control

1986 / 1990

CVS (Concurrent Versions System)

Created by Walter F. Tichy. Tracked files using folders, but lacked integrity checks—corrupting partial uploads and failing on binary files.

2000

Subversion (SVN) & BitKeeper

SVN solved CVS integrity bugs and binary handling using a Centralized (CVCS) architecture. BitKeeper pioneered early DVCS concepts for Linux.

2005 - Present

Git & Mercurial Revolution

When BitKeeper revoked Linux's free license, Linus Torvalds created Git and Olivia Mackall created Mercurial—popularizing Distributed VCS.

CI/CD Pipelines & Deployment Environments

🔄 Continuous Integration (CI)

Automatically compiles code and runs unit/integration test suites on every pull request to catch bugs early.

📦 Continuous Delivery (CD)

Automatically packages build artifacts and staging builds after successful CI passes, preparing them for deployment.

🧪 Staging Environment

A replica server matching Production used by QA for testing features, data migrations, and configuration updates.

🚀 Production Environment

The live server environment where real end-users interact with your application.

Module 2: CLI & Unix Essentials

Mastering terminal commands is essential for performing version control operations efficiently.

Core Unix Terminal Commands

pwd

Print Working Directory: displays full path to current folder.

ls -la

Lists all files including hidden ones (starting with .) in detailed list layout.

cd path/to/dir

Change Directory to specified target location.

mkdir -p dir1/dir2

Makes directories recursively including parent folders.

touch index.html

Creates a empty new file of any specified extension.

cp source dest

Copies files or directories from origin to destination.

mv source dest

Moves or renames files and directories.

cat file.txt

Reads out or concatenates file content to standard output.

less file.txt

Opens file contents paginated for easy reading.

history

Prints out recent commands executed in terminal session.

man <command>

Displays technical manual page for a command (e.g., man ls).

code .

Opens current workspace directly inside VS Code.

Reading ls -l File Prefixes

d Prefix

Indicates the line item is a Directory / Folder.

l Prefix

Indicates the item is a Symlink / Shortcut Link.

- Prefix

Indicates the item is a standard Regular File (text, image, script).

Pipes, Redirection, GREP & VIM

| Pipes

Feeds the output of command A into input of command B.
ls | wc -w or cat file1.txt file2.txt | wc -w

< > Redirections

0 < Stdin: cat < input.txt
1 > Stdout: ls -l > output.txt
2 > Stderr: ls /bin/usr 2> error.txt

🔍 GREP Searches

grep Sam names.txt (Partial match)
grep -i sam names.txt (Case insensitive)
grep -w Sam names.txt (Exact word match)

📝 VIM Workflow

1. Press i to enter Edit/Insert mode.
2. Write code/script (e.g., #!/bin/bash).
3. Press Esc key then type :wq! to write, quit, and save.

Module 3: Git, GitHub, Branching & Conflicts

Deep dive into core Git workflows, remote management, branch controls, and resolving merge conflicts.

SSH Key Authentication

Generates asymmetric public/private key pairs locally and uploads the public key to GitHub for passwordless pushes.

The 3 States of Git

State 1

Modified (Working Dir)

Files created, deleted, or updated locally. Git recognizes changes but isn't tracking them in a snapshot yet.

State 2

Staged (Staging Area)

Changes marked using git add to be included in the upcoming snapshot loading dock.

State 3

Committed (Local Repo)

Snapshot permanently written into the hidden local .git database folder using git commit.

Branch Management & Cleanups

git branch

Lists all local branches and highlights active branch with asterisk.

git branch feature-1

Creates a new branch named feature-1 without switching to it.

git checkout feature-1

Switches your active workspace context to branch feature-1.

git checkout -B feature-1

Creates branch feature-1 and immediately checks it out.

git branch -m new-name

Renames the currently checked out local branch to new-name.

git push -u origin main

Pushes local main branch and sets remote origin as upstream source.

git remote prune origin

Deletes stale local tracking branches that no longer exist on GitHub remote.

git pull

Executes git fetch followed by a git merge into current local branch.

Resolving Merge Conflicts & Feature Branching

⚡ Merge Conflicts

Occurs when Git cannot automatically merge conflicting changes (e.g., Developer 1 and Developer 2 edit same lines on Feature.js on separate branches). Resolved manually by picking changes or rebasing.

🌿 Feature Branch Workflow

Standard software team practice: isolate individual tasks/bugs on dedicated feature branches before submitting Pull Requests (PRs) into main production.
