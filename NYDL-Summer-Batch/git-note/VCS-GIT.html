1. What is Version Control System (VCS)?

A Version Control System (VCS) is a smart "time machine" for your project code. It tracks every change made over time so you can review history, restore old files, and collaborate with others without overwriting code.

Old Way

Centralized VCS (CVCS)

Examples: Subversion (SVN), Perforce

A single central server holds the entire project history. Developers check out files from this central server.

  • ❌ Single Point of Failure: If the central server crashes, nobody can commit or view history.
  • ❌ Requires Internet: You cannot save snapshots offline.
Modern Standard

Distributed VCS (DVCS)

Examples: Git, Mercurial

Every developer clones a full copy of the entire repository history onto their local computer.

  • ✅ Works Offline: You can stage, commit, and view history without internet.
  • ✅ Full Redundancy: Every team member has a full backup of the whole project.

Understanding Git vs. GitHub vs. GitLab

🔧 Git

The local CLI tool installed on your computer that tracks changes and saves commit snapshots on your hard drive.

octocat GitHub

A cloud hosting platform for Git repositories. Adds social collaboration, PRs (Pull Requests), issues, and team access.

🦊 GitLab

An alternative cloud platform & DevOps tool for Git repositories, popular for self-hosted enterprise pipelines (CI/CD).

2. First-Time Setup & Remote Connection

Before committing code, you must introduce yourself to Git locally and link your local project to a cloud repository on GitHub.

Step 1

Configure Identity

Tell Git who you are so your name is attached to every commit snapshot. 

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
Step 2

Initialize Local Repo

Turn any local folder into a Git-monitored repository.

cd my-project-folder
git init
git branch -M main
Step 3

Connect to GitHub

Link your local repository to a fresh cloud repository created on GitHub. 

git remote add origin https://github.com/user/repo.git
git push -u origin main

5. The 80/20 Rule: Most Used Git Commands

In daily professional development, you will use 20% of Git commands 80% of the time. Master these core commands first!

git init

Initializes a new empty Git repository inside your current folder.

git status

Shows the state of your working directory and staging area (modified, untracked, or staged files).

git add <file>

Moves changes from the working directory to the staging area. Use git add . for all files.

git commit -m "msg"

Saves staged changes as a permanent snapshot in your local repository with a message.

git log --oneline

Displays a list of all past commit snapshots in chronological order.

git push origin main

Uploads local commits from your machine to the remote GitHub repository.

git pull origin main

Fetches and merges latest changes from GitHub down to your local computer.

git clone <url>

Downloads an existing GitHub repository onto your local computer.
